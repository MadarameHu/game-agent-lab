目标：为 Coding Agent 的 Agentic RL 准备可执行任务、环境和可靠 reward。World Model 的游戏内交互数据作为后续伴随采集，不作为本阶段验收主线。

**本次确定了 10 个主选工程候选、35 个工程内任务设计方向，以及 2 个备选。尚未生成 1200 个任务。** 3 个原工程已有本地运行和任务验证记录；7 个新候选仅完成固定版本、源码、资源引用与许可证盘点，尚未运行引擎或实现检查器。

## 素材结论

首批扩展所需模型、棋子、球拍、敌人、音效等已在上游工程中找到，不必先建设素材生成系统。**资源文件存在不等于已成功导入，也不能据此保证能够产出 1200 个有区别的任务。**

- Kenney 新增三消与 FPS：代码 MIT；README 声明随附图像／模型／音效 CC0；FPS 字体另有 OFL 许可文本。
- 官方示例采用仓库 MIT，已记录目录内单独声明。Dodge 背景音乐为 CC-BY 3.0，字体 OFL，需保留相应声明。
- 备选 JRPG 的字体许可文件未在附近找到；备选 Physics Platformer 的音乐单独授权未核清。暂不纳入主选，核清或替换后再考虑。
- 3D 平台跳跃与城市等已有工程继续保留现有 source.json 和许可证，不把工程内所有素材笼统标成同一种许可。

## 任务类型与难度

统一覆盖六种类型：布局与可达性、输入与状态机、游戏规则、存档与生命周期、真实缺陷修复、素材接入与可验证UI。视觉风格好坏暂不作为程序 reward 的主干。

先按结构标三档，之后用目标小模型在固定预算下校准：

| 档位 | 主要特征 | 示例 |
| --- | --- | --- |
| 易 | 局部逻辑、少量状态、明确边界 | FPS生命恰好归零时死亡。当前源码使用 `<0`，这是源码发现，尚待运行复现 |
| 中 | 多个状态或规则配合 | 无效三消交换不扣步；Pong得分后重新发球且终局禁发球 |
| 难 | 跨模块、较长行为链或复杂物理 | 装填中切枪并保留弹药；存档失败保护；动态障碍重规划 |

35 个方向不是 35 个已经校准的独立任务族，也不是 1200 个实例。同机制在不同工程里的迁移版本需标记关联；不能仅靠改数字、改名称、改写query充数。

## 1200 与 BMK 的预留规则

暂按 **900训练 + 100开发 + 200测试** 预留，尚未建立实际任务列表或split文件。

测试200分三部分：同工程的未见任务族100、未见地图家族60、完全留出工程40。后者建议在工程准入后选定2个工程，其全部任务不进入训练或开发；目前不为尚未跑通的候选强行分配配额。

先分组，再划分：同一机制、错误注入模板、近似地图或参数变体归入同一家族。只有被指定为“整工程留出”的工程需要整工程隔离；已见工程测试仍按任务族、地图家族隔离。三个测试子集互斥，不重复计数。

官方源码盘点发现跨目录复用文件，已记录 lineage；其中包括音乐、字体、图片，不能把共享一个图片文件直接等同于任务泄漏，也不能把复制了控制器或修复模板的任务当作独立测试。

任务难度与reward调试使用训练／开发集合，不反复用最终200测试调方案。“未见工程”仅指本项目训练／开发未使用，公开源码是否出现在模型预训练中无法保证。

## 下一步只做两个小样本

1. 三消：选择“有限步数＋目标结算”，准备一条完整任务。
2. Pong：选择“计分＋终局停止”，准备一条完整任务。

每条先做到：完整工程能启动 → 基线确实不满足新需求 → 有通过候选 → 能拒绝具体错误候选 → 记录验证时延 → 再交给目标模型试跑。

检查器和reward在评测端维护，不默认提供给执行模型。用户需求与操作空间可见；无法从需求合理推出的任意阈值，不能藏在评测中强行要求。

通过这两条校准环境准备和检查器成本后，再决定扩到多少工程、每个任务族做多少实例。1200是目标规模，当前还没有足够证据保证质量和成本。
