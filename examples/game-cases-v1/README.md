## 每条记录

`cases/<id>/` 中：

- `task.json`：原始需求、素材、可修改范围和保留项。
- `project/`：可运行的修改结果。
- `contract/acceptance.json`：该任务的可执行检查标准和人工检查范围。
- `contract/baseline-hashes.json`：修改前文件哈希。
- `verification/`：检查器和测试脚本。
- `evidence/final/`：真实测试结果、日志及原生引擎截图。
- `evidence/root-review.json`：主 agent 对文件范围、来源绑定与验证覆盖的交叉核验。
- `manifest.json` / `trajectory.jsonl`：当前状态与阶段记录。
- `README.md`：该任务具体变化、测试方法和验证边界。

测试中为边界条件准备位置或状态的操作会标注为 fixture，不冒充玩家连续完成关卡。视觉、手感等判断保持人工待定；只有实际点击人工决定后才写入 `human-review.json`。

实际修复及失败证据已保留，包括平台路线漏收金币、通关面板裁切、赛车镜头前瞻方向反向；交叉核验后都已修复并针对问题重测。跳跃缓冲测试还修正过一次测试脚本的重复计时，未为迎合测试改变产品的时间窗口。每项 README 区分真实行为失败、测试问题和验证边界。

## 启动

从本目录运行：

```sh
python3 review/server.py
```

本机 Godot 路径位于 `runtime.json`。页面试玩会创建运行副本、先导入资源，并为每个 case 使用独立且持久的用户存档目录；这不会改变已验收工程。也可以直接用 Godot 编辑器导入各工程的 `project/project.godot`。不要用 `START_INPUT.py` 启动最终结果：它是准备阶段保留的初始状态入口，尤其会重新加载城市的原示例地图。

不同任务的自动 reward 只针对自身契约，分数相同不意味着难度或质量可直接比较。人工拒绝后，保留原候选和证据，再根据反馈生成新版本；页面本身不自动发起新的 coding agent。
